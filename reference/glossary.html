ServiceNow AI Agent Glossary

Reference Document · The canonical vocabulary for this course. Every lesson uses these terms exactly as defined here.
Why a glossary matters: ServiceNow's AI Agent terminology has shifted between releases (Xanadu → Yokohama → Zurich). This glossary uses current (Zurich) terms and flags legacy names so you're never confused by older documentation.
Agentic Workflow Object
The top-level container that coordinates multiple AI Agents toward a larger goal. Stored in the sn_aia_usecase table. Formerly called a Use Case. Nesting model: Tools → AI Agents → Agentic Workflows.
AI Agent Object
An autonomous system that reasons over a goal and calls one or more Tools to accomplish it. Defined by four mandatory fields: name, description, agentRole, and securityAcl. Stored in the sn_aia_agent table.
AI Agent Studio Object
The no-code/low-code workspace where you create, configure, test, and deploy AI Agents and Agentic Workflows. Access: All > AI Agent Studio. Requires the sn_aia.admin role.
AI Control Tower
The centralized command center (expanded in Zurich) to discover, govern, secure, observe, and measure all AI agents, models, and workflows across the instance. AI assets are tracked in the CMDB. Best practice: always deploy agents under Control Tower governance.
agentRole Field
The agent's identity field — answers "Who am I?" One of the three instruction fields, distinct from description (scope) and instructions (behavior).
Autonomous (execution mode)
A tool setting where the agent runs the tool on its own without asking the user first. SDK value: autopilot. Contrast with Supervised. Set per tool.
Channel
Where a deployed agent is available to users: the Now Assist / Otto Panel, Virtual Agent, record Analysis Panel, Microsoft Teams, Slack, SMS, email, or web chat.
description Field
The agent's scope field — answers "What problem does this agent solve?" Distinct from agentRole (identity) and instructions (behavior).
instructions Field
The agent's behavior field — answers "How should I act, and when should I use each tool?" Should be assertive, unambiguous, and updated every time a tool is added. Can encode approval gates (e.g., "NEVER modify without user approval").
Now Assist Skill Kit (NASK)
The toolset (shipped in Xanadu) for building custom generative AI Skills. Requires the sn_skill_builder.admin role. Not available on PDIs. Access: All > Now Assist Skill Kit.
Now LLM Service
ServiceNow's managed large language model service that can power agents and skills. Agents can also use external models via BYOK/BYOLLM.
BYOK / BYOLLM
"Bring Your Own Key / LLM" — a generic connector to use external LLMs (AWS, Azure, Google, IBM, OpenAI, etc.) instead of, or alongside, the Now LLM Service.
AI Agent Orchestrator
The LLM-driven reasoning layer that plans, sequences, and routes tasks across agents and tools — described by ServiceNow as a "digital manager." Reads tool names and descriptions to decide which to call.
Otto Panel Renamed
The in-product side panel where users converse with agents. Called the Now Assist Panel before Zurich; being rebranded ServiceNow Otto Panel.
ReAct Loop (Thought → Action → Observation)
The reasoning pattern an agent follows: it forms a Thought about what to do, takes an Action (calls a tool), observes the result (Observation), and repeats until the goal is met. Visible in the test panel's chain-of-thought view.
Skill (Now Assist Skill)
A single prompt-driven generative capability built in NASK. Sends a configured prompt (plus optional inputs and grounding data) to an LLM and returns output. A published+activated skill can be attached to an agent as a "Now Assist skill" Tool. Skills are building blocks; agents orchestrate them.
Supervised (execution mode)
A tool setting where the agent asks the user to approve before running the tool. SDK value: copilot. Contrast with Autonomous. Set per tool.
Tool Object
A capability an agent can invoke. Types include: Record operation (CRUD), Script, Subflow, Flow action, Now Assist skill, Search retrieval (RAG), Catalog item, Conversational topic, Desktop action, File upload, Knowledge Graph, Web search, and MCP. The tool's name and description tell the orchestrator when and how to use it.
Trigger Object
What launches an agent or workflow: a record event (create/update), inbound email, or a schedule — or none (invoked on-demand via the Otto Panel). Triggers deploy inactive and must be manually activated after testing.
Use Case Legacy
The old name for what is now called an Agentic Workflow. You'll still see "Use Case" in older documentation and in the table name sn_aia_usecase.

Key Tables

  • sn_aia_agent Table — stores AI Agents
  • sn_aia_usecase Table — stores Agentic Workflows (legacy: Use Cases)

Key Roles

  • sn_aia.admin Role — administer AI Agent Studio
  • sn_skill_builder.admin Role — build skills in NASK
  • sn_skill_builder.viewer Role — view NASK skills
