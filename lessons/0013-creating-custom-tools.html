Lesson 13: Creating Custom Tools

Duration: 18 minutes | Level: Beginner-Intermediate | Prerequisites: Lesson 12

Learning Objective

Build two custom tools by hand: a no-code Record operation tool and a Script tool. Learn the input/output rules that make tools actually work.

Custom Tool #1: A Record Operation (No Code)

Record operations let an agent do CRUD — Create, Read (lookup), Update, Delete — without any code. You configure them with a table and a condition builder.

Example: a "Look up open incidents for a caller" tool.

  1. Choose operation: Lookup
  2. Choose table: incident
  3. Build the condition: Active = true AND Caller = {{caller_id}}
  4. Write a clear description: "Looks up all active incidents for a given caller. Use when the user asks about their open tickets."
Referencing inputs: Use the {{...}} syntax to drop user-provided values into conditions — e.g. {{caller_id}}. The agent fills these in from the conversation.
⚠ Record operation limits (know these):
  • Output is String only — no rich record cards.
  • Reference fields aren't supported directly.
  • Journal fields (work_notes, comments) can't be written by CRUD — you need a Script tool for those.

Custom Tool #2: A Script Tool

When CRUD isn't enough, a Script tool runs custom JavaScript. Two rules make or break a script tool:

  • Read inputs via the inputs.<name> object.
  • Return data by populating an outputs object — that's how downstream steps receive your data.
// Script tool: add a work note to an incident
// input: incident_number (String), note_text (String)

(function execute(inputs, outputs) {
    var gr = new GlideRecordSecure('incident');   // use GlideRecordSecure, not GlideRecord
    if (gr.get('number', inputs.incident_number)) {
        gr.work_notes = inputs.note_text;          // journal field — needs a script
        gr.update();
        outputs.result = 'Work note added to ' + inputs.incident_number;
    } else {
        outputs.result = 'Incident not found: ' + inputs.incident_number;
    }
})(inputs, outputs);
Security rule from the SDK: Always use GlideRecordSecure (not plain GlideRecord) in agent script tools. It enforces the user's ACLs, so the agent can't read or write data the user isn't allowed to touch. (Fluent SDK)

Subflow & Flow Action Tools

You can also wrap logic built in Workflow Studio as a tool. The one rule to remember: inputs and outputs must be String type, or the orchestrator can't pass data in and out. We'll use these in Unit 6.

Every time you add a tool, update the agent's instructions to tell it when to use the new tool. A tool the agent doesn't know when to call is a tool it won't use.
