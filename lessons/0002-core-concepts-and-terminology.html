Lesson 2: Core Concepts & Terminology

Duration: 12-15 minutes | Level: Beginner | Prerequisites: Lesson 1

Learning Objective

Learn the four building blocks of ServiceNow AI Agents — Tools, AI Agents, Agentic Workflows, and Triggers — and how they nest together. This vocabulary is the foundation for everything you'll build.

The Nesting Model

ServiceNow AI Agents are built from a simple hierarchy. Once you see how the pieces nest, the whole platform makes sense:

🔧 Tools
individual capabilities
↳ grouped into
🤖 AI Agents
reason + call tools
↳ coordinated by
🔀 Agentic Workflows
orchestrate agents
Remember this sentence: "AI Agents can contain multiple Tools, and Agentic Workflows can contain multiple AI Agents." (ServiceNow, Building & Scaling AI Agents)

The Four Building Blocks

1. 🔧 Tool

A single capability an agent can use — like looking up a record, running a script, or calling a flow. The tool's name and description are critical: the agent's reasoning engine reads them to decide when and how to use each tool. Tool types include Record operations (CRUD), Scripts, Subflows, and Now Assist skills. (Full coverage in Unit 5.)

2. 🤖 AI Agent

An autonomous unit that's given a goal, then reasons about how to achieve it using its tools. Every agent has four required fields:

  • name — what it's called
  • description — its scope ("What problem do I solve?")
  • agentRole — its identity ("Who am I?")
  • securityAcl — its access controls

Agents live in the sn_aia_agent table. (Fluent SDK — Building AI Agents)

3. 🔀 Agentic Workflow

The top-level container that coordinates multiple agents toward a larger goal. Use one agent when tasks share a capability; use an agentic workflow when you need different capabilities working together (e.g., "fetch data THEN process it").

⚠ Terminology alert: Older ServiceNow docs call this a "Use Case." The current (Zurich) term is "Agentic Workflow." The underlying table is still named sn_aia_usecase, so don't be thrown when you see the legacy name.

4. ⚡ Trigger

What launches an agent or workflow. A trigger can be a record event (create/update), an inbound email, a schedule — or nothing at all (the user starts it on-demand from the Otto Panel). Important: triggers deploy inactive and must be manually turned on after testing.

Two More Terms You'll See Everywhere

AI Agent Orchestrator — the LLM-powered "digital manager" that plans and routes work across agents and tools.

Otto Panel — the side panel where users chat with agents (called the "Now Assist Panel" before the Zurich release).
