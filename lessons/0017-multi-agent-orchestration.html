Lesson 18: Multi-Agent Orchestration

Duration: 15 minutes | Level: Intermediate | Prerequisites: Lesson 17

Learning Objective

Learn when to use one agent versus a team of agents, how the orchestrator coordinates them, and the steps to build your first agentic workflow.

The Orchestrator: A Digital Manager

When multiple agents work together, the AI Agent Orchestrator coordinates them. ServiceNow describes it as a "digital manager" — it plans the work, decides which agent handles each part, sequences their actions, and passes data between them.

One Agent or a Team? The Decision Rule

From the Fluent SDK: use ONE agent when tools operate on the same table/capability. Use an AGENTIC WORKFLOW (multiple agents) when you have different capability types, or the task is "Fetch X AND do Y" / "Get data THEN process it." (Fluent SDK)
Use ONE agent Use a WORKFLOW (many agents)
All tools hit the incident table One agent reads HR data, another updates IT records
"Update the priority of this ticket" "Triage the case THEN draft a resolution"
≤ 5 tools, one capability Multiple distinct capabilities

Building an Agentic Workflow

The verified steps (ServiceNow docs — Create an agentic workflow):

  1. Go to All > AI Agent Studio > Create and manage > Agentic workflows > New.
  2. Define key requirements — the workflow's goal and scope.
  3. Define security controls — ACLs and run-as identity.
  4. Add a trigger — record event, email, schedule, or none.
  5. Select channels and access — where it's available.
  6. Test execution manually and Test user access.
⚠ Deploy agents first. An agent must be deployed before you can add it to a workflow. The workflow stores a team object whose members are the agents' sys_ids. Workflows live in the sn_aia_usecase table.
Real pre-built examples ServiceNow ships as agentic workflows: CSM's "Triage Cases," and ITSM's "Triage and Categorize Incidents" → "Investigate and Resolve" → "Wrap Up and Resolve." Each chains several specialist agents. You'll explore these in Unit 3.
