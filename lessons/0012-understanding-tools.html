Lesson 12: Understanding Tools

Duration: 15 minutes | Level: Beginner | Prerequisites: Unit 4

Learning Objective

Understand what Tools are, the main tool types available, and the two settings that matter most: execution mode (supervised vs. autonomous) and the all-important name + description.

Tools Are How Agents Take Action

An agent's reasoning is only useful if it can do something. Tools are the hands of the agent — each one is a discrete capability the agent can invoke: read a record, run a script, launch a flow, or call a generative skill.

The golden rule of tools: The agent's orchestrator reads each tool's name and description to decide whether and how to call it. A vague description = a tool the agent uses at the wrong time, or not at all. Write descriptions as if instructing a new employee.

The Main Tool Types

ServiceNow ships many tool types. As a beginner, focus on these four — they cover the vast majority of use cases:

Tool Type What it does
Record operation Create, look up, update, or delete records (CRUD) on a table using a condition builder. No code required.
Script Custom JavaScript for logic CRUD can't handle (e.g., writing to work notes). Uses GlideRecordSecure.
Subflow / Flow action Reuse logic built in Workflow Studio. Inputs and outputs must be String.
Now Assist skill A published generative skill built in NASK (Lesson 14).

Other types you'll meet later: Search retrieval (RAG), Catalog item, Web search, Knowledge Graph, Conversational topic, Desktop action, and MCP. (ServiceNow — AI Agent Tools)

Tool selection priority (from the Fluent SDK): prefer out-of-box tools first, then reference-based, then CRUD, and reach for a Script tool only when nothing else fits. Simpler tools are easier to maintain and safer. (Fluent SDK)

Supervised vs. Autonomous

Every tool has an execution mode, set per tool:

🙋 Supervised
asks user before running
(SDK: copilot)
🤖 Autonomous
runs on its own
(SDK: autopilot)
⚠ Safety principle: Make read operations (look-ups) autonomous — they're harmless. Make write operations (create/update/delete) supervised until you fully trust the agent. You can also encode approval gates in the agent's instructions: "NEVER modify a record without user approval."
