Lesson 20: Capstone Project

Duration: 45-60 minutes | Level: Culminating | Prerequisites: Units 1-6

Learning Objective

Put everything together. You'll design and build a complete, multi-tool agent — from concept to a governed deployment — applying every skill from this course.

The Brief: An "Employee IT Helper" Agent

Build an agent that helps employees with common IT requests: checking their open incidents, creating a new incident, and adding a note to an existing one. It's realistic, uses multiple tools, and exercises supervised vs. autonomous modes.

No entitled instance? Complete this as a design document — write out every field, tool, and decision. Designing well is 80% of the skill. Paste your design to me for review.

Your Checklist

✅ Part 1 — Design (apply Units 1, 4)

  • Write the three identity fields: description (scope), agentRole (identity), instructions (behavior)
  • Confirm this is one capability — should it be one agent or a workflow? Justify your choice (Lesson 17)

✅ Part 2 — Tools (apply Unit 5)

  • Tool A: Record operation (Lookup) — find the user's open incidents. Mode: Autonomous (read)
  • Tool B: Record operation (Create) — create a new incident. Mode: Supervised (write)
  • Tool C: Script tool — add a work note (journal field needs a script; use GlideRecordSecure). Mode: Supervised
  • Write a sharp name + description for each tool
  • Update instructions to say when to use each tool, with an approval gate on writes

✅ Part 3 — Test (apply Lesson 15)

  • Test bare (no tools) — does reasoning hold?
  • Add tools one at a time, re-testing after each
  • Run the same scenario 3+ times — is behavior consistent?
  • Read the chain of thought (ReAct loop) and confirm sensible Thought → Action → Observation steps

✅ Part 4 — Deploy & Govern (apply Lesson 18)

  • Set least-privilege ACLs
  • Choose a channel; start with a small audience
  • Add a trigger if needed — remember to activate it after testing
  • Confirm it's visible in the AI Control Tower

Success Criteria

Your agent is done when it can: (1) understand a natural-language IT request, (2) look up incidents autonomously, (3) create/annotate incidents only with user approval, (4) behave consistently across repeated tests, and (5) run under Control Tower governance.

Stretch Goals

  • Add a NASK skill that drafts a friendly incident summary, and attach it as a tool (Lesson 14)
  • Split into a two-agent workflow: a "triage" agent and a "resolution" agent (Lesson 17)
  • Have the agent hand off to a subflow for a multi-step provisioning task (Lesson 16)
