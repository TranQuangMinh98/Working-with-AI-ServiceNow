Lesson 11: Build Your First Agent (Hands-On)

Duration: 25 minutes | Level: Beginner | Prerequisites: Lessons 9 & 10

Learning Objective

Build a working agent end-to-end in AI Agent Studio, following the official step sequence. This is your first tangible agent — start simple, test, then grow it.

Follow along: If you have an entitled instance, do each step live. No instance? Read through and use the "dry-run" prompts — you'll still learn the flow, and can build later.

Our Goal: A "My Open Incidents" Agent

A simple agent that, when a user asks, looks up and summarizes their own open incidents. One capability, one tool — the ideal first build.

Step-by-Step Build

The official sequence (ServiceNow docs):

Step 1 — Open the Studio

Navigate to All > AI Agent Studio > Create and manage > AI agents, then click New. (You need the sn_aia.admin role.)

Step 2 — Define the specialty (identity fields)

Fill in the three identity fields from Lesson 9:

name:        My Open Incidents Assistant
description: Helps a user see and understand their
             own currently open incidents.
agentRole:   You are a helpful IT service assistant
             that reports on a user's open incidents.
instructions: When the user asks about their tickets,
              use the lookup tool to find active
              incidents where they are the caller.
              Summarize each as: number, short
              description, and priority. If none,
              say so clearly.
Test bare FIRST. Before adding any tool, open the test panel and chat with the agent. Confirm it understands its job and asks sensible questions. This is the golden method from Lesson 15.

Step 3 — Add one tool

Add a Record operation (Lookup) tool:

  • Table: incident
  • Condition: Active = true AND Caller = {{user}}
  • Description: "Looks up the current user's active incidents. Use when they ask about their open tickets."
  • Execution mode: Autonomous (it's a safe read)

Then re-test. Confirm the agent calls the tool and summarizes results.

Step 4 — Define security controls

Set the ACL / run-as identity so the agent only sees what the requesting user is allowed to see. Least privilege always.

Step 5 — Add a trigger (optional)

For a chat-driven agent, you can skip a trigger entirely and let users invoke it on-demand from the Otto Panel. If you add one, remember it deploys inactive.

Step 6 — Select channels & status

Choose a channel (e.g., Virtual Agent or the Otto Panel) and set the agent active.

You just built an agent! Notice the pattern: identity → test → one tool → test → secure → deploy. Every agent you ever build follows this same rhythm. Master it here.
⚠ AI-assisted creation: Studio can generate a first draft of an agent from a natural-language prompt. Great for a head start — but always review and refine the generated fields. Treat it as a draft, not a finished agent.
