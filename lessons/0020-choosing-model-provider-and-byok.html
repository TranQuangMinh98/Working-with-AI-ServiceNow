Lesson 15: Choosing the Model Provider (per Skill) & Setting Up BYOK

Duration: 20 minutes | Level: Intermediate | Prerequisites: Lesson 14

Learning Objective

Answer a very common real-world question: "Can I make one specific AI agent use Claude or GPT instead of the default model?" You'll learn what's possible today, the supported workaround, and how to set up a BYOK / BYOLLM (bring-your-own-model) provider.

The Question Everyone Asks

Say you build an agent that asks a user for some details and then generates a test suite. You'd rather that generation run on Claude or GPT than on the default model — but only for this agent. Can you do it?

Short answer: You cannot (yet) pick a model for one agent's orchestration. But you can pick the model one layer down — at the Skill level — and that's usually exactly what you want.

Where the Model Actually Gets Chosen

Recall the nesting model from earlier: Tools → Agents → Agentic Workflows. The important insight for this lesson is that an LLM is selected at more than one layer:

Agentic Workflow
  └─ AI Agent — orchestration LLM = instance default (no per-agent override yet)
      └─ Tool
         └─ Now Assist Skill — this skill's LLM = configurable per skill ✓

The model running the agent's reasoning loop (Thought → Action → Observation) is set at the instance level. A ServiceNow product team member confirmed this directly:

"We currently do not have granularity to choose specific models against specific AI agents' orchestration … [but] you can have Now Assist Skills that run in different models — the granularity is available today at the tooling level."

The Workaround: Put the Work in a Skill

Don't make the agent generate the test suite in its own head. Make a Skill do it, pin that skill to Claude/GPT, and expose the skill to the agent as a tool. The agent still orchestrates on the default model, but the heavy generation runs on your chosen model — for that flow only.

  1. Build a custom skill in the Now Assist Skill Kit — e.g. "Generate Test Suite" (this is the Lesson 14 workflow).
  2. Assign that skill to your chosen model provider. In the Now Assist Admin console → Manage model providers, the provider can be set at three levels: instance, skill group, or individual skill. Pick individual skill and choose, say, Claude.
  3. Expose the skill to your agent as a "Now Assist skill" tool.
  4. The agent gathers the user's input (orchestration = default model), then calls the skill (= your chosen model) to write the suite.
Net effect: test-suite generation runs on Claude/GPT exactly where you wanted — you just route it through a skill instead of the agent's own reasoning.

Setting Up a BYOK / BYOLLM Provider

BYOK (bring-your-own-key) / BYOLLM (bring-your-own-LLM) lets your instance call an approved external model using your own provider subscription. It's enabled through the Generative AI Controller. Supported providers include:

  • OpenAI — GPT-4.1 and GPT-4.1-mini (via Azure OpenAI)
  • Anthropic — Claude (e.g. Claude Sonnet, via Amazon Bedrock)
  • Google — Gemini 2.5 Flash / Pro

High-level setup (exact screens vary by release — verify on your instance):

  1. Install the Generative AI Controller plugin, plus the relevant provider spoke (e.g. the Amazon Bedrock spoke for Claude).
  2. Obtain credentials / a subscription with that provider (BYOLLM = you bring and pay for your own model access; it's separate from your Now Assist entitlement).
  3. Configure the provider connection (endpoint + credentials) via the spoke.
  4. In the Now Assist Admin console → Manage model providers, register the provider and assign it at the instance, skill-group, or individual-skill level.
  5. Review the model policies / guardrails, then test the skill against the new provider.
⚠ Requirements & caveats:
  • You need admin rights in the Now Assist Admin console.
  • BYOLLM incurs separate subscription charges with the third-party provider.
  • Consider data-residency and privacy — you're sending prompts to an external model.
  • Not available on PDIs — you need an entitled enterprise instance.
⚠ Version-dependent — check your own release. This area moves fast. ServiceNow announced that from July 9, 2026, third-party model providers begin becoming the default for out-of-the-box skills and agents — so "the default model" itself is shifting. And per-agent orchestration selection "may be introduced later," so if you're on a newer release, re-check whether native per-agent model choice has shipped.
