Lesson 3: How AI Agents Work

Duration: 15 minutes | Level: Beginner | Prerequisites: Lesson 2

Learning Objective

Understand the request-processing flow inside a ServiceNow AI agent — how the orchestrator, the LLM, and the ReAct loop turn a plain-language request into real actions.

1. The Orchestrator: the "Digital Manager"

When a request arrives, the AI Agent Orchestrator takes charge. It's the LLM-driven layer that reads the agent's instructions and available tools, then plans how to satisfy the request — deciding which tools to call, in what order, and (in a workflow) which agents to involve.

2. The LLM: the Reasoning Engine

Underneath, a large language model does the actual reasoning. ServiceNow can use:

  • Now LLM Service — ServiceNow's own managed models
  • External LLMs via BYOK/BYOLLM — OpenAI, Azure, Google, AWS, IBM, and more, through a generic connector

The model interprets language, decides what to do, and generates responses. It does not touch your data directly — it acts only through tools, which is what keeps it governable.

3. The ReAct Loop: Reason, then Act

Agents reason using a ReAct pattern — Thought → Action → Observation, repeated until the goal is met:
  • Thought — "The user wants VPN access reset. First I should verify who they are."
  • Action — calls the identity-lookup tool
  • Observation — reads the result, then thinks again
You can watch this whole loop play out in the test panel (Lesson 15).

4. Tools Are the Only Way to Act

Crucially, the LLM can only affect ServiceNow through tools. It can't secretly edit records. Every action flows through a defined tool, each governed by ACLs and an execution mode (supervised/autonomous). This is the architectural foundation of agent safety.

Why this design matters: Separating "reasoning" (the LLM) from "acting" (tools with ACLs) means you get AI flexibility and enterprise control. The agent is only ever as powerful — and as safe — as the tools and permissions you give it.

Putting It Together

Request → Orchestrator plans → LLM reasons in a ReAct loop → each Action calls a governed Tool → results return to the user. Multiply this across several coordinated agents and you have an agentic workflow (Unit 6).
